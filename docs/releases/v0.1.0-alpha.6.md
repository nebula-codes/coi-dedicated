# Alpha.6 — command expansion and authenticated startup

For Captain of Industry **0.8.7d**, compatibility **dedicated-prototype-6 / cmd1**. Update the server and every client together. Earlier alpha clients cannot join this revision.

## Changes

- Adds explicit codecs for all 87 command classes missing from the previous UI-observed inventory: 286 command classes and 287 schemas overall. This includes advanced train schedules/restrictions, wagon filters and train operations, industrial and world-map controls, cut/paste and quick actions, bulk road/decal tools, notifications, difficulty settings, and space-program controls.
- Uses native processors and their ordinary construction/Unity costs. Sandbox-only storage and instant terrain actions require the island's sandbox mode. Typed, bounded fields are validated against the authoritative world; arbitrary game object deserialization is not used.
- Preflights cut selections against the actual paste schema before removing anything. Cuts are limited to 128 supported machine/storage configurations; unsupported mixed selections and transports remain intact.
- Requires genuine Steam initialization and ownership validation before the server loads an island. This corrects the omitted startup prerequisite that could trigger the delayed pirate game-over in alpha.5. It does not repair an already-damaged save.
- Includes the alpha.5.1 client movement interpolation fix and the existing remembered join-key path.
- Includes a standalone Steam-check executable and Windows control executable in the server package for the experimental Wine container.

## Validation and limits

All new command schemas have valid-packet and malformed-input fixtures. Native tests exercise real game processors and selected effects on copied test islands; the [coverage ledger](../../research/multiplayer-command-coverage.json) separates successful native fixtures, expected native error paths, and wire-only coverage. Specialized copied configuration graphs remain limited; a codec does not prove every UI variant works.

The Windows startup regression placed 120 storage plans and ran 3,100 further simulation updates without the pirate callback, game-over, population loss, or vehicle scrapping. Two headless peers completed 400 updates each, two matching checkpoints each, speed transitions through 1–4, pause/resume, and native building placement. They ended at sequence 594 / step 116213 with identical raw simulation SHA-256 `1a2ebf61ec0a11f1fdc154f50f05d3b2cf6daa5db21084126f45d1e1a5606497`.

These are bounded fixtures. This release does not claim full gameplay parity, every new command replayed between real Unity clients, or multi-hour stability. Back up the island before updating.

## Docker / Portainer

The new candidate runs the Windows server and a genuine Windows Steam client in Wine on Linux amd64, with a persistent private profile and a password-protected setup desktop. Authentication-only mode is the default; it leaves the island unloaded. Read [the current Docker status and setup](../docker-portainer.md) before deploying. Runtime/Steam login and graceful stop validation must pass before the candidate is treated as a working server image. No working Docker image is announced by these Windows release notes. The old alpha.5 Docker image remains affected and must not be used for hosting.

Everyone still needs their own matching installed game. No game binaries, Steam credentials, island saves, or join/control keys are included in public packages.
