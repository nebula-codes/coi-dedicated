# v0.1.0-alpha.2 — Linux Docker / Portainer server

Adds a Linux x86-64 dedicated-server container for Docker Standalone and Portainer stacks. Requires the owner's complete Windows CoI **0.8.7d** installation mounted read-only; game files are not distributed in the image or Linux ZIP.

- Persistent saves and authentication keys under `/data`; automatically resumes `island.save`.
- Normal container stop/restart signals request a final save. Bootstrap cancellation preserves the active island.
- Runs as the non-root .NET `app` user. Only gameplay TCP **28551** is published; administration stays within the container.
- Authenticated status health check, Portainer logs, and a bundled control CLI for save, pause, resume, snapshot, and shutdown.
- Release-pinned image and portable server ZIP with SHA-256 verification. The .NET 10 runtime comes from Microsoft's container image.

Follow the [Portainer deployment guide](../docker-portainer.md). The Windows **0.1.0-alpha.1 multiplayer client** remains compatible; no client protocol or supported gameplay command changes are included in this server release. Use the existing [Windows client download](https://github.com/nebula-codes/coi-dedicated/releases/tag/v0.1.0-alpha.1).

The Windows browser manager is not exposed from this container. Portainer handles its lifecycle and logs. ARM, Docker Swarm, and long-running cross-platform multiplayer sessions are not validated. Existing alpha limitations remain: roads, transports, terrain editing, many specialized buildings, and other management commands are unsupported; automatic desync repair is not implemented.

Stop the old server before moving a live island. Transfer a consistent save and the private player key using the migration instructions; never upload either to the public repository.

## Validation

The final runtime image created a populated New Haven island with a read-only root filesystem and game mount, running as UID 1654. A Windows headless gameplay peer downloaded its snapshot and verified 100 authoritative ticks, pause/resume, and an unsupported-speed rejection. This is protocol/simulation testing, not an interactive Unity UI test or proof of complete cross-platform determinism.

Docker SIGTERM saved at step 145 and exited 0. Restart resumed that same island, progressed beyond the saved step, and retained the player key. Authenticated snapshot download also passed. Separate native Linux checks loaded an existing Windows save, and four process lifecycle tests exercised SIGTERM, SIGINT, repeated signals, and handler disposal.
