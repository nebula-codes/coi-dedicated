# Alpha.6.2 — browser server manager in Docker

The Portainer stack now includes the browser manager together with the native Linux game server. Open `http://YOUR-NAS-IP:28560/` to manage the island. The dashboard remains available when the game server is stopped.

- Start, stop, restart, pause, resume, and save; view status, player count, inventory, and logs.
- Create and download backups, import saves, restore while stopped, and download the player join key.
- Sign in with the private generated manager key at `/data/.manager/admin.key`. Browser sessions, settings, backups, and requested running/stopped state persist in the data volume.
- Existing `/data/island.save`, `join.key`, and `control.key` remain in place. Container shutdown saves and stops the child server; startup resumes only if it was left enabled in the dashboard.
- One stack manages one island. Paths and internal ports are fixed, and no Docker socket or privileged container is needed. Steam sign-in remains unnecessary on the server.

## Update in Portainer

Stop the old stack and retain an independent island backup. Replace its YAML with the [current Compose file](https://github.com/nebula-codes/coi-dedicated/blob/main/compose.portainer.yml), preserve the exact existing `COI_GAME_DIR` and `COI_DATA_VOLUME`, and set `COI_IMAGE=ghcr.io/nebula-codes/coi-dedicated:0.1.0-alpha.6.2`. Update with image re-pull enabled. The stack publishes game TCP 28551 and manager TCP 28560 by default.

Open the container console in Portainer with `/bin/sh` and run `cat /data/.manager/admin.key`; paste that key into the dashboard sign-in form. Keep it private. Players continue using their separate `join.key` and the NAS game port. Use the dashboard on a trusted LAN or private VPN. See the [complete setup and migration guide](https://github.com/nebula-codes/coi-dedicated/blob/main/docs/docker-portainer.md).

This release updates Docker hosting and the manager. **Existing alpha.6 and alpha.6.1 clients remain compatible** with the exact supported CoI 0.8.7d files. Windows users can keep the [alpha.6.1 client and manager downloads](https://github.com/nebula-codes/coi-dedicated/releases/tag/v0.1.0-alpha.6.1). The Linux ZIP includes the host, control tool, and browser manager; it is the payload used to build the image.

## Validation

Passed 31 HTTP/authentication checks, 14 storage checks, Windows/Linux process tests, and five isolated manager-lifecycle scenarios. Five real-island container integration groups verified authentication, pause/resume/save/logs, backup/download/import/restore, persistent settings and browser sessions, intentional stopped state, and restart. Existing island and keys were preserved. Gameplay shutdown exited 0 in 1.21 seconds; a separate bootstrap interruption exited 0 in 0.334 seconds without changing the committed island or source fixture. Browser sign-in, backup creation, settings refresh, preservation of unsaved edits across a container restart, and saving with refreshed container paths passed. The final archive has the same eight compiled assemblies as the real-island test payload.

Remote NAS deployment, human Unity clients against this release, and multi-hour sessions remain unverified. Prior alpha.6.1 simulation and multiplayer regression results are recorded separately in the setup guide. Game binaries, private saves, and credentials are not included in public packages.
